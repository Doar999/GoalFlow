## 摘要

目标创建时需要可恢复的澄清对话，后续消息需要版本校验、幂等和作业引用。新增对话、消息和模型调用表，以及目标对话读取、消息读取和异步提交的 HTTP 契约。契约 PR 只交付迁移、ORM 与端点桩；写入和作业接线在后续业务 PR 实现。

## 动机

产品 R02 与 D13 已确认自然描述进入澄清，规则层负责停止追问。开发设计 10 号第 6 节已确认目标创建时建立对话，但 T04 实现只保存了目标、档案草稿和规划会话。没有消息表，用户刷新后无法重建对话，也无法稳定引用来源消息。T08 需要记录模型调用用量，且未知用量不能记成零。

## 提案

创建目标时，目标、档案草稿、规划会话、对话和初始描述消息必须在一个写事务内提交。初始描述为空时只创建对话；对话允许未来扩展到任务或同目标多次澄清，不建立「每目标只能一条」唯一约束。用户再次提交文本时，返回已保存消息和澄清作业；相同 Idempotency-Key 与请求体返回原消息及作业。

刷新目标页时先读取目标关联的对话，再按对话内 sequence 分页读取消息。归属校验始终以服务端会话身份为准，跨用户 ID 与不存在 ID 都返回 404。模型回复只有成功提交档案候选后才发布为对话消息；失败作业由作业状态与事件解释，不能伪造成功回复。

## 技术细节

- 迁移 0008 建 `conversations` 和 `messages`。前者有 owner、可空 goal/task 关联和 revision；后者有 owner、conversation、正整数 sequence、user/assistant role、正文、可空 job 和客户端请求键。每个对话的 sequence 唯一。
- 迁移 0009 建 `model_calls`。记录 owner、job、provider、model、prompt_version、succeeded/failed 状态、可空输入与输出 token、可空耗时。03 号建议的 `estimated_cost` 保留可空列，尚无定价与币种定义时不填。表不保存凭证或提示正文。
- `GET /api/goals/{goal_id}/conversations` 返回关联对话与 revision；`GET /api/conversations/{id}/messages` 按 sequence 分页；`POST /api/conversations/{id}/messages` 接收文本和 expected_revision，要求 Idempotency-Key，首次与重放均返回 202，响应包含消息和作业。
- 当前契约只接受文本。附件与材料归 T11 的公共契约；不把未建的引用字段作为已确认输入。
- T04 的 `create_goal` 在后续业务 PR 通过对话模块的明确 Interface 完成原子写入。T08 不直接更新目标或规划会话内部表。澄清作业在 T07 已确认的条件提交协议内更新草稿，提交前复查输入 revision。

## 替代方案

- 只用档案草稿的 `initial_description` 存文本：无法表达后续轮次、顺序、修正引用和作业状态，排除。
- 把对话消息塞进 `planning_sessions` 的 JSON：消息增长会频繁改同一行，难以分页和逐条来源引用，排除。
- 在目标行加唯一 `conversation_id`：把首版交互约束误固化成永久一对一，任务对话与再澄清都会返工，排除。
- 在消息提交路由同步等待模型：断线后无法依靠 T07 作业恢复，也违反异步作业协议，排除。

## 影响与迁移

两条迁移只新增表，不改现有列，能独立回滚。已有目标没有对话；业务 PR 读取时应允许空列表，不臆造旧消息。前端需要从导出的 OpenAPI 重新生成类型，T10 可先按 202 和消息列表契约开发。T14 #29 仍独立评审。
