# 完成定义与评审清单

## 1. 完成定义（DoD）

一个 PR 只有全部满足以下条目才算完成。**"代码写完了"不等于完成。**

### 通用

- [ ] `bash scripts/check.sh` 通过（格式化、lint、类型、锁文件、契约漂移）。
- [ ] `bash scripts/test.sh` 通过，输出已贴进 PR。
- [ ] 改动只落在交接卡声明的可修改路径内（`git status` 自查）。
- [ ] 无新增 `# type: ignore` / `any` / `@ts-ignore`，或已在同行注明理由。
- [ ] 无凭证、无真实用户数据、无本地绝对路径进入提交。
- [ ] 交接卡已更新：进展、决策与假设、验证结果、未决问题。
- [ ] PR 模板填写完整，含真实验证命令与 AI 使用声明。

### 涉及公共契约时额外要求

- [ ] 契约变更已单独成 PR 并先行合并，本 PR 不夹带 schema / 迁移改动。
- [ ] `openapi/goalflow.yaml` 与前端生成类型同步，无漂移。
- [ ] 新增错误码已加入 `contracts/errors.py` 单点枚举。
- [ ] 破坏性变更已显式标注，并说明对已有数据和前端的影响。

### 涉及数据库时额外要求

- [ ] 迁移单一目的，文件名含工作包编号。
- [ ] 迁移可回滚，或已在文件头写明人工回滚步骤。
- [ ] 在**与生产同构的 SQLite 配置**上执行过升级与回滚，输出已记录。
- [ ] 若迁移走了 batch 模式的表重建：已逐列核对数据与唯一索引都完整保留。
- [ ] 未修改任何已合并的迁移。

### 涉及业务规则时额外要求

- [ ] 用户数据隔离已测：另一个用户访问被拒。
- [ ] 版本竞争已测：过期 `expected_revision` 返回 `REVISION_CONFLICT`。
- [ ] 幂等已测：重复提交不产生第二份业务结果。
- [ ] 时间预算不出现总额与剩余额度混用。

### 涉及模型调用时额外要求

- [ ] 使用模拟模型的部分在界面与交付说明中明确标识为模拟。
- [ ] 模型不可用、超时、结构化输出校验失败三条路径都有明确行为。
- [ ] 凭证在响应、日志、错误详情中均已脱敏。
- [ ] `openai` 与 `anthropic` 两个 provider 分别验证，**不以其中一个通过代替另一个**。
- [ ] chat model 的 `max_retries` 已显式设置，与 Celery 重试共用同一调用预算。
- [ ] LangGraph 图在作业结束后无遗留框架状态，未引入 checkpointer。

## 2. 评审清单

评审者按下面顺序看，**先看契约与边界，再看实现**。实现里的小问题可以留评论，契约和边界的问题必须打回。

### 范围与边界

- 改动是否超出该工作包声明的范围？有没有"顺手改的"文件？
- 有没有绕过 `05-module-contracts.md` 的 Interface 直接操作其他模块的状态？
- 契约变更是否混在了业务实现 PR 里？

### 需求依据

- 实现依据的是"已确认"结论，还是把"建议 / 待定"当成了事实？
- 新引入的默认值有没有记录在交接卡或 RFC 里？
- 命名是否使用 `CONTEXT.md` 的术语，还是出现了同义自造词？

### 正确性

- 并发与竞争：两个请求同时到达会怎样？Worker 重启后会怎样？旧 Worker 晚返回会怎样？
- 事务边界：失败时回滚干净吗？有没有跨事务的部分成功？
- 权限：每个路径参数里的对象 ID 都校验归属了吗？
- 时间：时区和本地日期有没有隐式转换？

### 测试质量

- 如果实现有 bug，这些测试会失败吗？还是只是把实现抄了一遍？
- 有没有冻结不该冻结的实现细节（调用次数、私有顺序、import 关系）？
- 数据库相关的断言是在与生产同构的 SQLite 配置上验证的吗？连接级 pragma 设了吗？

### AI 相关

- AI 使用声明填了吗？AI 生成量大的部分，作者能解释清楚吗？
- 有没有虚构的库 API、不存在的配置项、看起来合理但没验证过的用法？
- 有没有为了过 CI 而弱化或删除既有测试？

### 安全

- 有无凭证泄漏到代码、配置、日志、错误详情？
- 错误响应的 `details` 会不会带出其他用户的数据？

## 3. 打回标准

以下情况直接打回，不进入细节讨论：

- CI 未通过。
- 声称验证过但 PR 里没有真实输出。
- 契约变更与业务实现混在同一 PR。
- 改动了工作包范围外的路径且未说明。
- 修改了已合并的迁移。
- 提交中包含凭证。

## 4. 合并后

- squash merge，提交信息用 PR 标题（Conventional Commits 格式）。
- 删除功能分支。
- 更新交接卡：把完成的部分移出"进行中"，保留未决问题。
- 如果本次收敛了某个"建议"状态的结论，**同步更新对应设计文档的状态标记**。这一步经常被忘，忘了下一个人的 AI 就会再犯一次同样的猜测。
