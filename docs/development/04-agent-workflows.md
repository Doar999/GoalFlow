# Agent 工作流与状态设计 v0.1

状态：实施设计建议；承接已确认产品流程。采用显式 Python 工作流，结构化输入输出及持久化状态。流程模块负责规则，模型负责理解和生成。

编排选型已确认：首版自研，模型接入采用官方 SDK 加薄封装，不采用 LangChain/LangGraph。下述状态、接口及默认值仍为实施设计建议。自研范围限于本产品步骤、持久化、等待/恢复和变更规则；数据库、队列及模型通信继续复用既定组件。

## 1. 分开维护三类状态

目标生命周期：draft → active ↔ paused → completed/stopped。draft 只有用户开始执行后变为 active；完成目标不能仅由任务勾选率触发。达成型目标检查成功标准，维持型目标按周期复盘且永不进入 completed。完成/终止由用户确认，终态不可逆，仅提供 24 小时撤销窗口与"以此为起点新建"。形态由档案的时间边界推导。完整规则见 [目标形态、生命周期与结束规则](../product/12-goal-lifecycle.md)，实现基线见 [目标生命周期与结束实现基线](17-goal-lifecycle-design.md)。

建计划会话：clarifying → profile_review → route_review → plan_review → activated。路线或计划生成中的状态由关联 job 显示，不将业务状态覆盖为 running。用户返回修改上游档案时，下游预览标记 stale；已启用的原计划保持当前版本直至新版本正式应用。

后台作业：queued → running → succeeded/failed/cancelled/stale；可重试错误进入 retry_wait 再回 queued。等待用户选择属于业务会话状态，不保留一个持续占用 Worker 的任务。

任务执行：proposed → pending → in_progress → partial/completed/cancelled；partial 可继续执行，pending 可直接完成轻量任务。blocked 由依赖、开放阻碍和能力约束计算；今日延期属于反馈而非自动永久取消任务。取消、恢复和误操作更正走显式命令。验证状态与执行状态独立。

## 2. 目标创建与方案选择

| 步骤 | 输入与模型产出 | 服务端检查与持久化 | 页面体验 |
| --- | --- | --- | --- |
| 需求澄清与策略路由 | 用户表达、已知档案；输出已知事实、假设、缺口、内部领域判断及少量追问 | 校验来源与结构，不把推测标成用户确认事实；选择领域策略并保存消息和档案草稿 | 只围绕目标事实对话，可跳过非关键问题；不要求用户选择领域 |
| 档案确认 | 目标结果、起点、投入、限制、成功标准 | 用户确认后形成档案版本；关键缺口未解决时明确暂定或建议诊断 | 可编辑摘要 |
| 路线生成 | 档案、领域策略、其他目标占用；一次输出同口径的路线集合 | 校验约束、共享预算与真实差异；改变范围/期限明确标注，不伪装成等价方案 | 对比后选择与微调 |
| 计划生成 | 选定路线和微调；输出完整阶段、里程碑、依赖及开始日起七日任务批次 | 检查无环、时间、任务标准和能力可用性；保存草稿，不占正式额度 | 计划总览和七日预览 |
| 开始执行 | 用户确认草稿版本 | 重新读取各目标预算，事务校验并启用；过期或不可行则返回原因 | 成功后进入今日页 |

没有可行路线时返回约束冲突；所有方案都不满意时询问具体原因并更新候选。生成失败保留已有输入，不要求重新创建目标。首周为开始日起连续七个本地日期；默认开始日按当天剩余容量选择今天或下一个可用日期，用户可以修改。

领域判断属于编排内部状态。置信度不足时采用通用策略，并提出能够区分规划方法的事实问题；禁止把“学习、健身还是通用”作为必答问题。后续事实触发策略迁移时重新检查档案和计划，只有实际内容的重大变化需要用户确认。

澄清的详细就绪条件、问题数量和草稿来源规则见 [目标澄清引擎](10-clarification-engine.md)。业务规则层最终计算 `needs_input`、`review_ready` 或 `blocked`，模型不能自行放宽成功标准、安全阻断或事实来源要求。

路线生成采用整组候选输出、确定性预算与差异校验，具体接口及微调边界见 [路线生成与比较引擎](11-route-engine.md)。模型可以提出推荐解释，只有通过服务端硬过滤的路线才具备推荐资格。

计划采用阶段/里程碑完整、近期任务滚动细化的结构。详细覆盖不足三天时生成下一七日 task batch；正常展开不创建新 plan version。具体边界见 [计划生成、滚动细化与启用引擎](12-plan-engine.md)。

## 3. 每日安排

1. Beat 按用户时区检查需准备的日期；页面打开时可补齐缺失安排，两条路径使用同一个去重键。
2. 读取当前活动计划、任务状态、依赖、周额度与当天覆盖值，形成带 revision 的快照。
3. 缺少近期任务内容时才调用模型细化；已有明确任务的排期由代码计算。
4. 排期模块输出任务顺序、投入、预算余额或冲突；不能仅因空闲时间增加自动追加任务。
5. 检查修改是否为允许的小调整。影响关联目标、期限或成功标准则生成待确认建议。
6. 短事务验证快照仍有效，保存安排版本和变更原因；并发变化则重新计算，不强行写入。

排期采用已确认的分层优先级：必须项和硬约束优先，弹性任务再考虑周投入缺口、紧迫度、用户 focus/rank 和防长期饥饿。模型不参与最终排序或擅自牺牲目标；无法满足时呈现可选调整。休息日允许空清单，无反馈不视为失败，过期任务不自动全部搬到次日。具体见 [多目标排期与冲突引擎](13-scheduling-engine.md)。

## 4. 执行反馈与复盘

普通任务一键记录；练习提交答案；交付任务提交材料。写入反馈后立即更新可确定的执行状态，不等待模型。需要验证的任务创建独立作业，检查材料可读性、完成标准和输出依据。

无法访问链接、材料不足或模型失败分别展示，不能当作验证通过。验证结果只基于实际可读材料；上传资料内容作为待分析数据，不能更改系统权限或触发任意工具执行。

每日回顾可跳过。Agent 基于近期有效记录产生观察和建议：区分没反馈、没完成、结果未达标；对时间不足、难度估计偏差和目标冲突给出不同处理，不一律追加任务。

反馈保存、验证和调整分别处理：先同步追加 checkin 并更新执行投影，再异步验证材料，最后由规则层按已批准计划包络判级。完整接口与并发规则见 [执行反馈、验证与调整引擎](14-feedback-adjustment-engine.md)。

## 5. 计划变更与用户确认

模型输出 change_proposal，包括变更内容、理由、受影响目标与任务、投入变化、基础版本和不确定项。后端计算实际影响并判级，不能接受模型自行声称“这是小调整”作为授权。

仅调整未开始任务顺序、在允许日期范围内移动/拆分，或由领域规则在同一里程碑和已批准投入内执行补救，可以自动执行。任何增加已批准投入、里程碑/期限变化、成功标准变化、移动锁定/进行中任务或关联目标影响进入 pending。未定义允许范围时采用保守规则，不自动延期或增加投入。

确认时事务重新检查版本，确认与应用原子提交；若已过期，返回 stale 并展示新差异，不能沿用旧确认。拒绝后保留当前计划与冲突。相同被拒建议不重复自动应用。

## 6. 结构化输出与模型调用

每个生成结果包含 schema_version、基于的业务版本、内容、假设和待确认事项。Pydantic 校验类型后，还要执行归属、依赖、预算和状态校验。模型返回的实体 ID 必须属于服务端提供的允许集合。

调用上下文按顺序装配：系统规则、已确认目标档案、领域策略、当前计划、相关执行记录、会话摘要与最近消息。业务事实从数据库取，摘要仅辅助；不默认注入全部用户目标，独立目标只共享排期必要的时间信息。

对话回复、计划生成和材料验证使用不同输出契约与提示版本。限制单次输出和修复次数；非法结构可有限修复，预算/目标不可能的业务问题交给用户取舍，不无限重试。

记录模型与提示版本、延迟、用量、错误。供应商超时有限重试；可能产生重复模型费用，业务结果依然只提交一次。具体模型和最大调用次数待供应商评估。

## 7. 后台恢复与前端事件

提交操作先事务写 jobs/outbox，返回 job_id；分发失败重试 outbox。Worker 用租约抢占任务，网络调用在事务外；重试须复查输入版本、取消状态及已提交结果。

SSE 持久化事件包括 queued、started、stage_completed、awaiting_confirmation、completed、failed，使用 job_id + sequence 补读。临时 token 事件可不持久化，断线后查询最终消息/产物；不承诺逐 token 重播。连接终止不取消作业。所有查询与事件订阅都校验 owner_id。

## 8. 验收场景

| 场景 | 预期 |
| --- | --- |
| 两个目标同时启用争用最后 60 分钟 | 只有按最新预算校验通过的提交生效；另一请求返回冲突 |
| 页面和 Beat 同时请求今日安排 | 相同输入只对应一个有效作业及当前安排 |
| 生成过程中用户修改目标 | 旧结果标为过期，不覆盖新档案或计划 |
| 重复点击开始执行 | 返回原结果，不重复创建任务或扣预算 |
| Worker 超时后旧进程晚返回 | 旧租约不能提交，当前有效尝试决定结果 |
| 用户完成练习但得分不达标 | 执行完成和未掌握并存，后续按依赖要求处理 |
| 未关联目标被建议共享任务 | 后端拒绝自动建立依赖或复用完成判定 |
| 用户拒绝延期建议 | 原期限保留，问题可见，不自动重提并应用 |
| 隔天回来或 SSE 断线 | 恢复持久化状态，不重复生成或误判未完成 |
| 修改 URL 访问其他用户记录/作业事件 | 拒绝访问，不泄露内容 |

测试分层：排期和状态规则单元测试；真实 seekdb 事务、并发与迁移集成测试；固定模型输出用于流程测试；少量真实模型评估检查生成质量，不用一次模型回答代替规则测试。
