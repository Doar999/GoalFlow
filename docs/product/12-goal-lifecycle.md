# 目标形态、生命周期与结束规则 v0.1

状态：首版产品方案已确认，对应 PRD 决策 D12。本文补齐 [Agent 工作流](../development/04-agent-workflows.md) 第 1 节标注的"重新开启规则待定"，并定义暂停、结束与形态归属的完整语义。

## 1. 两种目标形态

目标形态 `kind` 由目标档案中的**时间边界**推导，不新增提问：

| 时间边界 | 形态 | 用户可见差异 |
| --- | --- | --- |
| 固定日期 | 达成型 | 有期限、有里程碑倒计时、可被标记完成 |
| 弹性周期 | 达成型 | 有预计周期但无硬期限，可被标记完成 |
| 持续维持 | 维持型 | 无完成日期，按周期回顾保持状态，不会被标记完成 |

形态是目标档案中**可见且可编辑**的字段，随档案一并确认。与内部领域（`domain`）不同，形态必须对用户可见——它直接决定界面上有没有完成日期、有没有周期回顾。

追问时使用用户能理解的事实问题，例如"你希望在某个时间点达成，还是长期保持这个状态？"，不要求用户选择"达成型还是维持型"。用户后续修改时间边界可以改变形态，按计划变更规则处理结构影响。

## 2. 状态与允许的转换

```text
draft ──► active ◄──► paused
             │           │
             └─────┬─────┘
                   ▼
          completed / stopped   （终态，不可逆）
```

- `draft` 只在用户点击开始执行后变为 `active`，草稿不进入今日页也不占排期。
- `active ↔ paused` 可反复切换。
- `completed` 与 `stopped` 都是**终态，不可恢复为 active**。
- 终态目标保留全部历史记录，可查询、可回顾。

## 3. 达成型：怎么算完成

两条已确认前提：完成不能仅由任务完成率触发；完成由用户确认。三种实际情形分别处理：

| 情形 | 处理 |
| --- | --- |
| 全部成功标准验证通过 | 主动提示"看起来已达成，标记完成吗"，仍等用户确认 |
| 部分标准达成 | 展示逐条状态，用户可选择「完成并记录未达成项」或「继续推进」；系统不判定"差不多了" |
| 计划执行完但标准未达成 | **不自动完成，也不判定失败**。提示"计划已执行完，目标标准尚未达成"，提供四个出口：延长期限、追加任务、接受现状并完成、终止 |

第三种情形不是新状态，而是 `active` 下的一个提示。延长期限与追加任务都可能超出已批准的计划包络，此时按重大变化请求确认。

## 4. 维持型：周期回顾，不产生完成

- 成功标准是**周期性**的，例如"每周三次训练"、"每周保持五小时学习"。
- 按回顾周期评估达成情况，输出**保持中 / 偏离 / 中断**三态。
- 维持型目标**永远不会进入 `completed`**。
- 默认回顾周期为一周，与周投入预算同一节奏；可设为双周或每月。属首版默认值，由版本化策略管理。
- 结束方式只有两种：用户显式「不再需要」进入 `stopped`，或用户修改时间边界使其转为达成型。

回顾结果为"偏离"或"中断"不等于失败，也不自动终止目标；按反馈调整规则处理，必要时提出降低频率或调整内容的建议并等待确认。

## 5. 暂停与恢复

暂停的完整语义：

- 目标退出排期候选，不再滚动生成任务批次。
- **周投入需求从共享预算中释放**，其他目标可以使用这部分时间，但不自动填满，也不自动追加任务。
- **不改写任何任务状态。** 进行中的任务保持进行中，已完成记录保持不变；恢复后可以接着做。有进行中任务时仍允许暂停。
- 跨目标依赖受影响时必须展示：若另一目标的任务依赖本目标的任务，那些任务转为计算态 `blocked`，暂停操作前后都要让用户看到这个影响，不能静默生效。
- 记录暂停原因与时间，不设自动恢复。

恢复的行为：

- 不把积压任务搬到今天，先了解当前情况和可用时间。
- 重新检查共享周预算；若已被其他目标占满，展示冲突而不是静默压缩本目标投入。
- 若计划的详细覆盖日期已过期，重新生成任务批次，不沿用过期批次。

## 6. 结束、撤销与以此为起点新建

- `completed`：达成型且用户确认达成，允许附带未达成项的记录。
- `stopped`：用户主动放弃或不再需要，以及维持型的正常结束。
- **`stopped` 不显示为失败。** 维持型目标正常结束也走这个状态。

终态不可逆，但提供两个出口：

1. **撤销窗口**：结束操作后 24 小时内可撤销，回到结束前状态。用于应对误操作，不是通用的重新开启。属首版默认值。
2. **以此为起点新建**：继承原目标的档案内容（可编辑），生成新的目标、新的档案版本和新的计划。原目标保持终态并记录派生关系。

选择不可逆是为了避免语义冲突：已经判定通过的成功标准、已经完成的里程碑、已经过期的计划日期，在"恢复"语义下都没有干净的答案。维持型目标天然适合新建模型——"今年保持每周三练"结束后开始"明年"，本来就是新目标。

## 7. 活动目标数量与预算

**不设活动目标数量上限。** 数量是假约束，五个小目标可能比两个大目标更轻；共享周预算才是真约束。

因此：

- 启用新目标时检查全部活动目标的周投入总和，超出共享预算则明确展示缺口并要求取舍，不静默降低任何目标。
- 暂停目标释放其周投入需求，这是用户主动腾出空间的正常手段。
- 维持型目标会长期占用预算，这是其固有属性，需要在启用时如实展示。

## 8. 验收场景

- 用户说"我想长期保持每周锻炼三次"，档案中形态显示为维持型且没有完成日期，用户可以直接改成有期限的形态。
- 用户从未被问过"这是达成型还是维持型"。
- 达成型目标的全部成功标准通过后，系统提示可以标记完成，但不自行完成。
- 三条成功标准有两条通过时，用户可以选择完成并记录未达成项，记录中能看出哪一条未达成。
- 任务全部完成但成功标准未通过时，目标既不被标记完成，也不被标记失败，四个出口都可见。
- 维持型目标在回顾中显示"偏离"，目标仍是活动状态，不产生完成状态。
- 暂停一个有进行中任务的目标不被拒绝，且恢复后该任务仍是进行中。
- 暂停被其他目标依赖的目标时，界面展示哪些任务将变为受阻。
- 暂停后其他目标不会被自动追加任务来填满释放出的时间。
- 暂停两周后恢复，今日页不出现两周积压任务，而是先确认当前情况与可用时间。
- 已完成的目标没有"重新开启"入口，但有"以此为起点新建"，且新目标继承档案内容后可编辑。
- 误点完成后 24 小时内可以撤销，撤销后回到原状态且历史完整。
- 同时推进七个目标不被数量规则阻止；启用第七个时若周预算不足，明确展示缺口。
