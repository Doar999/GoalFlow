# 今日执行页

状态：页面作为默认首页已由用户确认；以下布局、交互及规则为讨论稿。

已确认首版采用每日任务清单，展示单项预计时长和合计投入，不展示自动分配的起止时刻。未来可切换到具体时段安排，首版不提供模式切换控件。

## 页面目的

用户打开应用即可了解今天做什么、为什么做、需要投入多少时间，并能开始任务、记录结果或请求帮助。对话提供持续支持；阶段计划和历史日志提供独立查看入口。

## 信息顺序

1. 今日概况：日期、今日涉及目标、总预计投入与可用时间、已完成任务数量。任务完成率不表述为目标完成率。
2. 下一步行动：突出一项当前可执行的任务，展示任务目的、预计时间、完成标准和开始入口。
3. 今日其他任务：合并各目标任务，每项标注所属目标并支持按目标筛选；按可执行顺序展示，区分待开始、进行中、已完成和今日延期；依赖未满足的任务说明原因。
4. 今日记录：保留用户反馈、Agent 辅助产物和计划调整说明；有内容时展示，历史按日期查看。
5. 随时求助：针对当前任务发起对话，自动带入相关任务与目标上下文；明确当前对话针对哪个目标或任务。

## 核心交互

- 点击开始后打开任务内容和所需材料，不强制开启计时器。
- 完成任务时按任务性质收集必要反馈：简单任务支持轻量确认，测验或交付型任务使用相应结果。不要求每项任务写长篇日志。
- 支持部分完成、遇到困难和今天做不了；这些操作不会直接被当作目标失败。
- 支持修改今天可用时间并预览重新安排结果；不能静默覆盖已开始或已完成的任务。
- 每项任务可以查看安排原因；用户可将任务标记为今天必须处理或锁定当前安排。锁定导致容量冲突时显式提示，不自动挤掉其他必须项。
- 已确认可用时间取自每周默认额度，并支持当天临时调整。建议展示额度来源（每周默认或今日调整），区分全天额度与剩余时间。
- Agent 辅助工作单独显示准备中、可用或失败，不能因辅助产物生成成功自动完成用户任务。
- 已确认每天提供一次可跳过的简短回顾，不要求每项任务写日志；提醒方式待定。

## 任务反馈（已确认）

采用轻量记录为主、关键任务再验证的方式。

| 任务类型 | 反馈方式 |
| --- | --- |
| 普通行动任务 | 一键完成，可选补充耗时和感受 |
| 学习练习任务 | 提交答案或练习结果，Agent 给出反馈 |
| 交付型任务 | 记录产出，必要时附文字、链接或附件，对照完成标准检查 |
| 部分完成或遇到困难 | 保留进展，可简单说明情况，作为调整依据 |

用户自报完成与 Agent 已验证的结果区分展示。

落地细则建议：任务执行状态与结果验证状态分开保存。验证未通过不抹去已投入的努力；例如做完练习但未达到掌握标准，可记录练习已完成、掌握标准未达成，并建议补充练习。材料无法读取或证据不足时显示待补充或无法验证，不能标记已验证。完成要求应在任务开始前可见，不在提交后临时追加。附件格式、容量和链接读取范围已确认，见 [Agent 辅助能力与证据验证范围](10-agent-assistance-and-verification.md)。

反馈动作、验证状态及调整分级的完整建议见 [任务反馈、验证与计划调整](09-feedback-and-adjustment.md)。反馈保存不得等待模型；验证与复杂调整可以异步完成。

## 关键页面状态

| 状态 | 展示与行动 |
| --- | --- |
| 尚未创建目标 | 引导描述目标并开始澄清 |
| 目标或路线尚未确认 | 展示当前草稿和继续规划入口，不生成已承诺的每日安排 |
| 已生成计划但尚未开始执行 | 提供计划总览与首周安排的检查入口；用户点击“开始执行”后才纳入正式每日清单 |
| 正常执行日 | 概况、下一步任务、其他任务和记录 |
| 休息日或没有安排 | 明确说明原因，允许用户主动调整；不为了填满页面生成任务 |
| 当天任务已完成 | 展示执行总结和可选回顾，不自动追加任务 |
| 多日未反馈后返回 | 询问近期实际进展和今天可用时间，不直接认定此前任务全部失败 |
| 任务生成或辅助执行失败 | 说明失败，保留已有安排，提供重试或继续可执行任务的入口 |
| 目标暂停或结束 | 展示状态与总结，提供恢复或创建新目标的入口。已结束目标只提供"以此为起点新建"，无重新开启入口（见 [目标生命周期](12-goal-lifecycle.md)） |

## 状态呈现与提醒范围

已确认（对应 PRD D11）：**首版只做状态呈现，不做主动通知。**

- 用户打开应用时看到当天任务、待处理冲突、多日未记录提示和目标状态变化。
- **不承诺任何主动通知**，界面措辞避免使用会让用户以为会被通知到的说法。
- 首版**不请求浏览器通知权限**——不提供的能力不应弹出权限请求。
- 首版不做邮件提醒。D07 已确认无邮件服务也能运行，引入 SMTP 会带来配置、送达率与退订一整套问题。

技术前提：浏览器 Web Push 依赖的推送通道在中国大陆桌面浏览器基本不可达，因此首版不做主动推送是环境限制下的如实取舍，不是暂缓实现。站外通知方式留待后续，接入时先单独评估通道可用性（对应 Q06）。

## 待讨论

- 已确认支持多目标并行、统一协调时间及分层优先级；具体拖拽、focus 控件和冲突选择器的视觉交互待细化。
- 首发平台已确认为网页端；响应式布局、移动浏览器覆盖范围和导航形式待细化。

## 后续开发需细化

- 按用户时区定义今天，跨日不自动改写实际完成时间和历史安排。
- 每日安排与计划版本关联；重复打开首页不重复生成或随机改变任务。
- 执行记录与任务状态分开保存，支持更正误操作并保留调整原因。
