# 开源定位与用户模型配置

已确认：项目目的为开源 Agent；用户可选择模型并配置自己的凭证。以下具体界面和实现规则为建议。

## 用户体验

已确认首版支持 OpenAI 和 Anthropic 两个 provider，经 LangChain 统一接入，并支持自定义服务地址。Anthropic 不推迟到后续，也不强制经 OpenAI 兼容接口转换。建议 OpenAI 下提供 Responses 与 Chat Completions 两个明确 API 选项，Anthropic 不需要该选项；具体能力按服务和模型测试，不承诺覆盖供应商的所有端点。

建议流程：新增配置 → 填写参数 → 保存 → 主动测试 → 设为默认 → 开始规划。地址填写 API 基础地址，避免重复拼接 /v1；模型名称可手动输入，模型列表接口不是必需项。测试分别显示基本生成、结构化输出和流式结果，不以连通成功代表能力全部通过。

本地无鉴权模型可不填 Key，受实例管理员出站策略约束。远程部署的 localhost 指服务器而非浏览器用户的电脑，容器部署需填写后端可达的服务地址。

设置中提供模型配置：名称、provider（OpenAI/Anthropic）、API 模式（仅 OpenAI）、服务地址、模型标识、API Key、是否为默认配置。预设减少填写负担，自定义地址满足用户自己的服务；不宣称所有模型能力通用。

保存和连接测试分开。测试前说明会向选定服务发送最小测试请求，可能产生用量，不发送用户目标和日志。保存后凭证只显示已设置或脱敏状态，支持替换、禁用和删除。

没有有效配置时仍可查看已有计划和记录执行；首次需要生成时引导配置。错误区分凭证、地址、模型名称、能力不支持、限流和超时，不能把不同错误都提示为 Key 错误。

建议首版一个默认配置用于规划、对话和复盘，可保存多个候选并手动切换。不同步骤分别选择模型作为后续可选能力，不在首版自动增加复杂路由。切换模型不修改已生成的计划，也不自动重新生成任务。

## 能力与上下文

用户选择实际调用的服务；系统仍需校验结构化输出。供应商不支持原生结构化输出时，只能在经过验证的文本解析加校验路径上运行，不能保证所有模型都适用。工具调用、流式返回及向量能力分别标识，缺失能力明确提示。

说明执行时会将必要目标上下文发送到用户选定的模型服务；按目标范围组装上下文，不向所有已保存供应商同时发送。用量未知或自定义服务无价格信息时显示未知，不伪装成免费。

## 开源交付建议

提供自部署文档、示例配置、数据库迁移和备份说明。示例不包含真实密钥、私人数据和真实用户账号。许可证已确认为 Apache-2.0，仓库已公开托管；正式发布时间与推广方式仍待定。

托管实例的个人模型配置需要信任实例运营者：服务端运行时必须解密并调用，不能承诺运营者绝对无法接触密钥。自部署者持有自己的加密主密钥。
