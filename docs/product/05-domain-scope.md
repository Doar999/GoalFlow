# 首版领域范围

已确认：学习、健身、通用三类均支持核心闭环，分别落实专属澄清问题、任务类型和反馈规则。项目交付先作为通用类中的场景。以下具体配置是细化建议，尚未逐项确认。

| 类别 | 专属澄清内容 | 任务类型 | 执行反馈与结果 |
| --- | --- | --- | --- |
| 学习 | 当前水平、目标能力、现有材料、薄弱项与使用场景 | 学习、练习、复习、测验 | 练习结果、错误类型、困难描述；区分做完和掌握 |
| 健身 | 当前活动基础、限制、可用场地器材与目标指标 | 训练、恢复、测量、执行记录 | 完成情况、实际投入、主观状态及用户提供的指标；不根据勾选推断身体变化 |
| 通用 | 预期产出、完成条件、现有资源、期限与依赖 | 准备、制作、检查、交付、复盘 | 产出说明和材料，对照完成标准；材料不可读时不标为验证通过 |

## 共同规则

三类共享路线比较、计划草稿确认、每日清单、多目标时间协调、轻量反馈与变更权限。类别只改变专业内容和判断依据，不绕开确认、预算或数据隔离规则。

建议使用同一领域配置契约：澄清字段、必需信息、任务类型、结果验证规则、调整约束和提示版本。领域由 Agent 内部推断并路由，不显示为创建目标时的用户选项；项目交付使用通用配置下的场景规则，暂不建设独立子系统。

当信息不足时，Agent 询问具体事实，例如“你希望能通过考试，还是能在工作中实际使用？”，不能把内部判断转嫁给用户，例如“请选择学习或通用”。用户始终确认目标档案、路线和计划内容，而不是确认领域标签。

## 首轮试用验收样例建议

- 学习：用户完成练习但未达掌握要求，执行完成与验证未达标可同时展示。
- 健身：用户反馈今天状态不适合执行原任务，系统保留记录并按领域约束处理，不只按空闲时间补满训练。
- 通用：制作一个简单网页，先有产出定义再拆任务；缺少上游资料时后续任务说明依赖。
- 三类同时存在时，共享一天总额度；独立目标不自动建立任务依赖。

各领域专业规则、规则来源与验证标准已确认，见 [三类领域专业规则与责任边界](11-domain-rules.md)；本文不给出具体训练处方或学习效果承诺。
