# 三类领域专业规则与责任边界 v0.1

状态：首版产品方案已确认。本文补齐 [首版领域范围](05-domain-scope.md) 第 26 行留下的空缺：三类领域的专业规则从哪里来、以什么形式约束生成、以及产品承诺到哪里为止。

## 1. 规则来源与责任边界

已确认采用**版本化结构约束 + 模型填内容**：仓库维护可测试的规划结构规则，模型在这些约束内生成具体内容，服务端在模型输出后重新校验。

因此必须明确一句话：

> 领域策略提供的是**规划结构约束**，不是专业内容处方。

由此确定产品承诺范围：

- 不提供医疗、康复、营养、心理咨询建议。
- 不承诺学习成绩、考试通过率或身体指标达成。
- 不声称计划内容有专业机构或教学法背书；有背书的只是"计划在结构上自洽、可执行、可验证"。

选择这条路线的理由是可审计：结构约束能写成确定性判定，能写回归测试，用户更换模型时计划骨架不变，只有具体内容措辞变化。这与已确认的"切换模型不修改已生成的计划"一致。

## 2. 硬约束与软偏好

[探索记录](00-product-discovery.md) 已列出每个领域策略必须定义的 8 项内容。本文要求这 8 项都拆成两层，因为只有第一层能被执行：

| 层 | 含义 | 违反时的处理 |
| --- | --- | --- |
| 硬约束 | 服务端可确定性判定的条件 | 模型输出被拒绝并要求重新生成；有限次数后向用户展示约束冲突 |
| 软偏好 | 写入提示、影响生成倾向 | 不作为拒绝理由，不写入验收条件 |

下文各领域的数值都是**首版默认值，由版本化策略管理**，后续可根据实际试用调整；调整走策略版本，不在代码里散落魔数。

## 3. 学习领域

**硬约束**

- 成功标准必须可检查，或档案中已明确先执行诊断阶段。
- 当前基础标记为未知时，计划必须包含诊断任务，且排在第一个里程碑之前。
- 计划必须包含至少一个测评类里程碑，不能只由学习任务的完成数判断目标达成。
- 练习与测验任务必须携带判分标准；系统出题的默认掌握阈值为正确率 80%（见 [辅助能力与证据验证范围](10-agent-assistance-and-verification.md)）。
- 复习任务必须引用其所复习的学习单元，不接受内容空泛的"复习"任务。
- 新知识引入与其首次复习之间必须有间隔，默认复习间隔序列为 1、3、7、14 天。
- 单个学习单元任务的预计时长上限为 90 分钟，超过必须拆分。

**软偏好**

- 小单元高频优于长单元低频。
- 先诊断再确定起点，而不是先假设水平。
- 已出错的内容优先进入后续复习队列。

## 4. 健身领域

已确认生成具体训练内容，但受硬约束过滤。

**三条不做**：不诊断疾病、不开处方（训练处方、饮食计划、补剂）、不生成康复训练。

**硬约束**

- 用户声明的健康限制进入**阻断集合**：服务端据此过滤被禁止的任务类型，模型输出若包含被阻断内容一律拒绝。阻断不是写在提示里让模型自觉遵守。
- 每连续 3 天至少包含一个恢复日或低强度日。恢复日允许是空清单，排期器不得因为当天有空闲时间就往里填训练任务。
- 周训练量（总时长或总组数）相对上周的增幅上限为 10%。
- 不生成具体饮食计划、热量目标或补剂建议。
- 测量类任务只记录用户提交的数值，不据此推断身体变化或健康状况。
- 健身任务的依赖不得以"验证通过"作为解锁条件，只能要求"执行完成"。理由见 [辅助能力与证据验证范围](10-agent-assistance-and-verification.md) 第 4.3 节：一张手环截图读不出来就不该卡住整条计划。该约束由服务端在计划校验时判定，违反的候选整体拒绝。
- 出现风险信号时（用户自述疼痛、孕期、术后、心脏或血压问题等），收窄到低强度、低冲击范围，并提示咨询专业人士；**不因此拒绝整个目标**。
- 只采集与执行安全直接相关的健康信息，不建立健康档案。

**软偏好**

- 先保证动作质量，再提升强度。
- 同一肌群不在连续日安排高强度内容。

## 5. 通用领域（含项目交付场景）

**硬约束**

- 每个交付型任务的完成标准必须写成可逐条判断的条目，与产出验证方式对齐。
- 任务依赖必须无环。
- 每个里程碑必须有明确验收方式，不接受只有日期的里程碑。
- 产出定义先于制作任务：没有确定产出是什么之前不生成制作任务。
- 缺少上游资料时，后续任务必须声明该依赖，不能写成可独立执行。

**软偏好**

- 优先安排能产生可验证最小产出的任务。
- 不省略检查与复盘类任务。

## 6. 主领域与次要特征

- 只有一个**主领域**驱动硬约束和任务类型。
- **次要特征**已确认降级为目标档案中的事实字段：进入提示上下文影响生成内容，但不追加硬约束，也不组合出新的规则集。
- 主领域与次要特征都不向用户展示为分类选项，用户确认的始终是档案、路线和计划内容。

这样首版只需覆盖三套主领域规则的测试，不必测试规则组合。

## 7. 领域迁移

目标事实变化时 Agent 可以迁移主领域策略，按当前阶段分三种处理：

| 时点 | 处理 |
| --- | --- |
| 档案确认前 | 自由迁移，记录迁移原因 |
| 档案已确认、计划未启用 | 用新策略重新生成路线与计划草稿，旧草稿标记为过期 |
| 计划已启用 | 生成待确认建议；同时改变成功标准时按目标变化处理 |

计划启用后的迁移必然改变计划结构，因此按已确认的计划包络逻辑属于重大变化。用户确认的是迁移后的计划内容差异，不是领域标签本身。进行中和已完成任务不被迁移改写。

## 8. 验收场景

- 用户说不清当前英语水平时，计划的第一个里程碑之前存在诊断任务，而不是直接假设起点。
- 学习计划中每个复习任务都能点开看到它复习的具体内容。
- 模型生成了一个 150 分钟的学习任务时被拒绝并重新生成为可拆分的单元。
- 学习目标的计划中至少有一个测评里程碑；仅把学习任务全部勾完不判定目标达成。
- 用户声明膝关节问题后，训练任务中不出现被阻断的动作类型，且该过滤在服务端生效而非仅靠提示。
- 连续三天都被安排了高强度训练的计划被拒绝；恢复日为空清单时不被排期器填入训练任务。
- 用户询问该吃什么或要不要吃蛋白粉时，明确说明不提供饮食与补剂建议。
- 用户自述孕期后，建议范围收窄并提示咨询专业人士，目标本身仍可继续推进。
- 交付任务的完成标准是可逐条判断的条目，不是一句笼统描述。
- 目标事实变化触发领域迁移时，已启用计划不被静默重排，而是展示结构差异并等待确认。
- 用户更换模型配置后重新生成任务批次，计划的阶段、里程碑与硬约束结果保持一致。
