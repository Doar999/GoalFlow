# 目标执行 Agent：首版 PRD v0.1

状态：汇总评审稿。已确认需求来自当前讨论；“建议”及“待定”均未自动成为用户决策。当前仅完成文档设计，尚无应用实现。项目名称待定。

## 1. 产品定位与用户

已确认项目定位为面向个人用户、开箱即用的开源 Agent。用户可以直接注册登录，自行选择模型并配置凭证；不设置邀请码或管理员审批。自部署是首版交付的一部分；许可证已确认为 Apache-2.0，仓库已公开托管，正式发布时间与推广方式仍待定。

帮助用户通过对话把目标转为可执行计划，并通过每日任务、反馈及调整持续推进。首版为面向个人用户的网页应用，主要使用环境为中国大陆。同一实例可服务多个相互隔离的个人账号，但不提供团队协作空间。

用户可以同时推进多个目标，选择目标独立推进或与其他目标关联；所有目标统一协调时间。已确认首版支持学习、健身和通用三类，各自落实专属澄清问题、任务类型和反馈规则；项目交付作为通用类场景。具体字段和验证细则见 [首版领域范围](05-domain-scope.md)。

首轮试用要验证的是用户能否理解方案、开始执行、在现实变化后继续推进。任务勾选率不能单独代表目标成效。

## 2. 已确认首版需求与验收

| 编号 | 需求 | 可观察的验收条件 |
| --- | --- | --- |
| R01 | 用户注册并登录网页应用 | 无需邀请码即可用账号标识和密码注册、登录；登录后只能访问本人的数据 |
| R02 | 对话澄清目标 | 从自然描述开始，每轮只追问少量关键事实；保存可编辑目标档案，事实、推断、假设和未知可区分；就绪后主动停止追问 |
| R03 | Agent 自动选择领域策略 | 用户只需描述目标；系统根据事实加载不同领域字段和任务规则，不要求用户选择或确认分类 |
| R04 | 先比较完整路线再微调 | 可以比较路线的投入、方法和成果，选择后提出修改，再生成计划 |
| R05 | 检查滚动计划后开始 | 完整阶段与里程碑、开始日起七天详细任务可查看；未点击开始执行的草稿不进入正式待办，详细覆盖不足三天时再滚动展开七日窗口 |
| R06 | 今日执行页为首页 | 展示当天任务、单项及合计预计用时；首版不自动分配具体时刻 |
| R07 | 多目标并行与隔离 | 独立目标不自动形成跨目标任务依赖；关联需明确对象，时间仍合并协调 |
| R08 | 每周默认额度与当天调整 | 按日期得到有效时间额度；当天临时调整不改后续默认额度 |
| R09 | 小调整自动、大调整确认 | 自动变更可看到原因；期限、成功标准、明显增加投入或关联目标影响先确认 |
| R10 | 保留执行进展 | 重排不覆盖已完成记录，不擅自替换进行中任务 |
| R11 | 轻量反馈与关键任务验证 | 普通任务可一键完成；练习/交付任务可提交结果；部分完成能保留进展 |
| R12 | 执行状态和验证状态分别展示 | 练习完成但未达标时能同时表达这两个结果 |
| R13 | 每日回顾可跳过 | 不填写回顾也能继续使用和执行任务 |
| R14 | 应用内辅助能力 | 支持规划、指导、复盘及约定的辅助产出；清单与边界见 [辅助能力与证据验证范围](10-agent-assistance-and-verification.md)，辅助产出不替代用户投入 |
| R15 | 用户自选模型与凭证 | 每位用户可以保存自己的模型配置；执行使用其选择，配置错误可定位且不影响已有任务记录 |

## 3. 建议补充的首版质量要求

| 编号 | 建议要求 | 验收方式 |
| --- | --- | --- |
| Q01 | 用户数据隔离 | 修改记录 ID、文件引用或作业 ID 不能访问其他用户内容 |
| Q02 | 重复操作不重复生效 | 重复启用计划和提交同一反馈，业务数据只生效一次 |
| Q03 | 生成可恢复 | 刷新页面、网络断开或 Worker 重启后能查询最终状态，无虚假成功 |
| Q04 | 冲突显式展示 | 超额预算或无可行方案时说明问题，不静默降低成功标准 |
| Q05 | 缺失反馈不等于失败 | 多日未登录返回后先了解现状，不自动堆积全部任务 |
| Q06 | 大陆环境验证 | 对实际部署网页、登录、模型与文件访问验证，不以框架名称代替可用性测试 |
| Q07 | 费用与故障可追溯 | 记录调用用量、耗时与错误；预算额度暂缓设定 |
| Q08 | 使用历史可解释 | 可查看原安排、反馈和调整原因，当前版本清晰 |

## 4. 核心用户旅程

首次使用：注册并登录 → 配置模型 → 设置默认可用时间 → 描述目标 → 澄清并确认档案 → 比较路线 → 选择与微调 → 查看计划与首周安排 → 开始执行。

日常使用：打开今日页 → 查看下一步与合计投入 → 执行/求助 → 记录完成、部分完成或困难 → 接收验证或调整 → 可选每日回顾。

现实变化：调整今天的时间或描述新限制 → 系统评估全部目标 → 小调整生效并解释，大调整等待确认 → 保留历史与已有进展。

## 5. 页面组成建议

- 今日：多目标清单、用时概况、任务详情、反馈和当日记录。
- 目标：创建入口、目标档案、路线比较、计划预览、关联及生命周期操作。
- 回顾：按日期查询记录、阶段结果、计划调整原因。
- 设置：每周额度、时区、账号及偏好。
- 对话面板：明确当前目标或任务上下文；首次澄清可采用完整对话页面。

今日作为首页已确认，其他导航与响应式范围属于设计建议。阶段计划不能因页面布局选择而省略。

## 6. 范围控制

已确认后续扩展：每日清单与具体时段模式切换、外部工具执行能力。

建议暂不纳入首版：付费订阅、营销获客系统、产品内多人共同编辑目标、独立原生 App、通用插件市场。多人开发协作与产品内多人协作不是同一需求。

## 7. 未决事项与推荐默认值

下面用于集中评审，未确认前不得静默作为固定规则；对相关任务实施形成输入依赖。

| 编号 | 未决事项 | 推荐默认值/处理方式 | 影响 |
| --- | --- | --- | --- |
| D01（已确认） | 首版领域深度 | 学习、健身、通用均支持，由 Agent 内部自动路由；用户不判断领域。落实专属澄清、任务与反馈，项目交付先使用通用策略。规则采用版本化结构约束加模型填内容，硬约束由服务端判定；次要特征降级为档案事实字段，不追加规则 | 领域规则与责任边界，详见 [文档 11](11-domain-rules.md) |
| D02（已确认） | 路线生成与推荐 | 默认最多三份，有几份可行方案就展示几份，不凑数；统一字段比较，只有依据明确时推荐，不强行产生唯一推荐 | 生成成本、比较界面与路线校验 |
| D03（已确认） | 滚动计划与开始日期 | 完整阶段和里程碑＋开始日起七天详细任务；覆盖不足三天时展开下一七日批次。今天有容量则默认今天，否则下一个可用日期；用户可修改 | 计划预览、任务批次与预算计算 |
| D04（已确认） | 默认目标隔离 | 默认独立推进，关联在计划启用前确认且必须写明具体任务关系；首版只支持任务先后依赖，不做成果复用。解除关联走变更提案并原子执行，不留残余依赖。任务最晚日期不可为空；"明显增加投入"为相对已批准基线累计增幅同时超过 10% 与 30 分钟 | 创建与依赖规则，详见 [文档 13](13-goal-links.md) |
| D05（已确认） | 多目标优先级和冲突 | 默认同等优先，用户可设置 focus 和目标顺序；硬约束先于弹性任务，随后考虑周投入、紧迫度、用户顺序和防长期饥饿。无法满足时提供取舍，不自动牺牲目标 | 多目标排期与今日页解释 |
| D06（已确认） | 自动调整边界 | 以已批准计划包络为界：投入、日期、里程碑、成功标准、锁定和目标关系均未越界时可自动调整并解释；任一越界则确认。连续两次摩擦触发诊断，至少三条可比记录后再校准估算 | 调整策略与反馈体验 |
| D07（已确认） | 账号方式 | 账号标识＋密码自由注册登录、服务端会话 Cookie；不使用邀请码，且无邮件服务也能运行 | 账号设计见开发文档 08 |
| D08（已确认双 SDK） | 模型接入范围 | 用户自选模型和凭证；首版兼容 OpenAI/Anthropic 官方 Python SDK，原生双路径；端点子集与能力门槛继续细化 | 真实模型集成与配置页 |
| D09（已确认） | 辅助能力清单 | 首版提供解释答疑、练习与测验生成、已提供材料整理、复盘草稿与交付骨架草稿；辅助产出不计入任务完成，且不得作为同一任务的验证依据。Agent 主动联网检索不纳入首版，保留能力位并明示"无检索能力"，不用生成内容冒充资料 | 辅助能力与来源展示，详见 [文档 10](10-agent-assistance-and-verification.md) |
| D10（已确认） | 附件范围 | 支持填写/粘贴文本、`.txt`、`.md`、图片与 PDF；不接受 Office 文档、压缩包、音视频及 `.svg`、`.html`。读图依赖用户所选模型能力，缺失时判为证据不足而非通过。支持读取用户提交的公开链接，不执行页面脚本，实例级出站开关默认开启 | 上传、链接读取与材料验证，详见 [文档 10](10-agent-assistance-and-verification.md) |
| D11（已确认） | 提醒 | 首版只做状态呈现，不做主动通知：不请求浏览器通知权限、不做 Web Push、不做邮件提醒。大陆桌面浏览器推送通道基本不可达，站外方式留待后续单独评估 | 调度与通知，详见 [今日执行页](01-today-page.md) |
| D12（已确认） | 目标形态与结束规则 | 达成型与维持型由档案的时间边界推导，形态在档案中可见可改；完成与终止由用户确认，维持型永不进入完成；终态不可逆，只提供 24 小时撤销窗口与"以此为起点新建"；暂停不改写任何任务状态并释放周投入；不设活动目标数量上限 | 状态模型，详见 [文档 12](12-goal-lifecycle.md) |
| D13（已确认） | 目标澄清方式 | LLM 提取语义与候选问题，Python 规则判断缺口、阻断和结束；草稿可恢复、来源可追踪，用户确认档案后才生成路线 | 澄清引擎与档案版本 |

首轮试用规模、注册防滥用策略及数据保留策略仍待细化。活跃目标不设数量上限，以共享周预算作为唯一实际约束（见 D12）。用户可使用自己的模型凭证；是否额外提供实例共享模型额度尚未决定。预算金额按用户要求暂缓讨论。开源模型配置设计见 [模型配置](06-model-configuration.md)。

## 8. 首轮试用观测建议

记录首次计划启用、首次任务反馈、用户修改方案的原因、调整接受情况、冲突频次、调用失败与单用户用量。结合实际产出或阶段测评评估是否推进目标，不预设未经讨论的增长或留存指标。
