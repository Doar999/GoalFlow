# 多目标协调 v0.2

状态：首版产品方案已确认。独立目标保持计划和任务边界，全部活动目标共享时间预算；排期先处理硬约束，再使用周投入、紧迫度、用户优先级和防长期饥饿规则。

## 已确认的产品决策

- 首版允许用户同时推进多个目标。
- 用户选择目标是否与其他目标隔离。
- 隔离表示计划与任务相互独立，时间仍统一协调；不表示数据隐私或访问权限隔离。
- 首版按日安排：展示今天做什么、各任务预计用时与合计用时，不分配具体起止时刻。
- 后续支持在每日清单和具体时段安排之间切换；不纳入首版实现。
- 每日可用时间采用每周默认额度加当天临时调整；用户无需每天重新填写。

## 时间额度规则

已确认：用户设置一周中各天的默认可用时间，并可当天临时修改。所有目标共同使用这份额度。

建议细则：

- 提供工作日和周末批量设置，也允许逐日修改；不替用户预设未经确认的时间承诺。
- 当天调整只覆盖当天，不改变每周默认值；修改长期默认值使用独立入口。
- 额度可设为零，表示当天没有可分配时间，不自动将当天任务堆积到次日。
- 区分全天总额度与当前剩余时间。用户说“今天还剩半小时”时不能将其误记为全天总额度；已投入时间未知时标记为估算或澄清。
- 缩减额度时保留已完成记录和已开始任务的进展，对剩余工作提出调整建议；不得为了满足新额度改写历史。
- 增加额度不自动填满空闲时间或追加任务，可提供可选建议。
- 修改每周默认值只影响后续安排；生效日期和受影响计划应明确显示。

## 目标关系与时间边界

已确认默认独立推进；关联必须明确对象及具体关系，不因内容相似自动建立依赖或复用完成结果。首版只支持任务先后依赖，成果复用不纳入首版。完整规则见 [目标关联、依赖与解除规则](13-goal-links.md)。

独立目标不建立跨目标任务依赖，不共享完成判定，也不因另一个目标的业务进展自动改写任务内容、成功标准或阶段结构。共享时间不足仍可能需要调整执行日期；这属于资源协调，不能被承诺为完全不受其他目标影响。

关联目标可以提出具体的任务先后依赖建议，由用户确认。依赖必须避免循环。某个目标变更时，展示受影响的任务及建议，不无限传播自动重排。首版不支持一份成果同时满足多个目标的完成条件；需要这种效果时用户在各目标分别记录。

所有目标使用同一份每日可用时间额度。各领域提交任务预计时长、可执行日期范围、依赖及是否允许拆分等约束，由统一调度形成每日清单，合计投入不得重复占用预算。首版不验证具体时段冲突；每日总时长可容纳任务，不代表已证明所有现实日程均无冲突。后台 Agent 工作不直接等同于用户投入时间，但等待结果可能影响后续任务。

时间不足时展示缺口与备选安排，不静默提高投入、删除任务或降低目标。若无法同时满足约束，应明确呈现冲突而非生成看似可行的安排。

例如今天可用 90 分钟，学习需要 60 分钟、健身需要 45 分钟：即使两个目标独立，也必须展示 15 分钟缺口。可以建议移动可调整任务；缩短任务需任务规则允许，增加可用时间需用户确认。

## 优先级与每日排序（已确认）

所有活动目标默认同等优先。用户可以设置当前重点目标、调整活动目标顺序，并把具体任务标记为今天必须处理或锁定当前安排。“今天必须处理”固定日期但仍允许调整清单顺序；“锁定”同时保留当前日期和分配分钟数。目标优先级只参与弹性任务的取舍，不能覆盖已开始任务、用户锁定、硬期限、安全限制或明确依赖。

排期按以下层级处理：

1. 收集已开始任务、用户锁定/今日必须任务、最晚日期为今天的任务，以及会阻塞近期任务的必要前置任务。
2. 如果这些必须项已经超过容量，保存冲突并全部展示，不自动删除其中一项。
3. 对剩余弹性任务，依次考虑本周相对计划投入的缺口、里程碑或期限紧迫度、用户设置的目标重点/顺序、连续性要求和连续未获安排的天数。
4. 同等条件下优先选择能适配剩余容量、依赖已满足并能减少频繁目标切换的任务。
5. 可拆分任务只有在剩余容量达到 minimum_session_minutes 时才分配部分分钟；不可拆分任务必须完整容纳。

防长期饥饿只提高弹性任务候选顺序，不能越过必须项。系统使用可解释的层级和原因码，不向用户展示伪精确综合分数。

## 周预算与日预算

计划启用时检查所有活动目标的每周预计投入总和；总需求超过共享周预算时先解决冲突，不能把问题推迟到每日排期。每日预算用于处理日期分布、任务约束和当天临时变化。

每日容量缩减后，先保留进行中和锁定任务，再在允许日期范围内移动弹性任务。容量增加时不自动填满；可以展示额外候选任务。无任务能满足剩余时间和最小单次时长时，允许保留空余时间。

每项安排保存原因，例如本周投入不足、期限临近、解除依赖、保持训练间隔或用户锁定。任务移动也保存原因及对里程碑的影响。

## 首页规则

显示所有目标合计投入与时间预算，合并呈现今日任务并标注所属目标。目标筛选只改变展示，不重新分配时间。每项任务可展开查看安排原因；存在无法解决的冲突时显示待处理提示，不用已安排状态掩盖超额。

## Agent 自主调整边界（已确认）

- 小调整自动执行并说明原因：在时间预算内调整未开始任务的顺序，或在允许范围内移动执行日期。
- 大调整先征求用户意见：改变目标期限、成功标准、明显增加投入，或影响关联目标。
- 保护已有进展：不覆盖已完成记录，不擅自替换正在进行的任务。

落地细则建议：自动调整必须满足已有任务依赖、可执行日期范围、用户锁定事项及领域约束，且不导致其他目标预算超额。尚未确定可移动范围时，不自行假定任务可以延期。跨目标调整先评估影响，再决定是否属于需确认的大调整。

需确认的变更作为建议保存，用户接受前原计划仍为当前版本；若原计划已不可行则明确展示冲突。自动执行与用户接受的变更都记录前后差异和原因。拒绝建议后保留原计划与未解决问题，不反复自动应用同一变更。

可移动日期范围与“明显增加投入”的判定阈值已确认，见 [目标关联、依赖与解除规则](13-goal-links.md) 第 5、6 节。

## 后续切换能力的设计建议

任务身份、完成标准和执行记录独立于排期方式。未来具体时段作为额外安排信息；切换模式不复制任务、不重置进度。时段不可容纳、固定安排以及模式切换后的提醒规则，在扩展阶段单独细化。
