# 执行计划生成与预览 v0.1

状态：首版产品方案已确认。采用滚动计划：完整阶段与里程碑、开始日起七天详细任务、详细覆盖不足三天时继续展开。

## 1. 计划层级

执行计划使用三层结构：

- **阶段（Phase）**：一段具有明确推进方向和退出条件的过程。
- **里程碑（Milestone）**：能够验证阶段是否取得预期结果的检查点。
- **任务（Task）**：用户或 Agent 可以直接执行、具有预计投入和完成标准的行动。

路线回答总体方法和取舍，执行计划回答阶段、里程碑及近期行动；每日安排只负责把当前可执行任务放入具体日期。三者不能合并为同一个可变任务列表。

## 2. 滚动细化范围

首次生成计划时：

- 完整生成计划周期内的阶段及主要里程碑。
- 生成开始日起连续七个用户本地日期的详细任务。
- 后续两至四周只展示阶段重点、里程碑和预计投入。
- 更远范围仅保留阶段方向、里程碑和重要依赖。

当活动计划的详细覆盖结束日期距离今天少于三天时，后台展开下一个连续七日窗口。正常滚动展开不改变路线、阶段或里程碑，因此形成新的任务批次，而不是新的计划版本。

阶段、里程碑、核心方法、成功标准或既有任务依赖发生实质变化时，才创建新的计划版本。修改任务说明或估算创建新的任务规格；每日顺序变化只创建新的每日安排。

## 3. 开始日期和首周

首周始终指计划开始日起连续七个本地日期，不按自然周截断。

开始日期分两步确定，两步都是确定性判定，不由模型决定：

1. **生成前预填**：今天剩余容量大于零时预填今天，否则预填下一个剩余容量大于零的日期，通常是明天。此时计划尚未生成、任务时长未知，只能按容量是否为零判断。
2. **生成后校验**：计划草稿生成后，检查开始日能否容纳当天安排的任意一项任务——不可拆分任务看预计时间，可拆分任务看最小单次时长。一项都容纳不下时，在预览中说明原因并建议改到下一个能容纳的日期，由用户确认。不静默改写用户已经看到的开始日期。

- 用户可以选择其他日期；修改开始日期后重新计算首周预览。
- 开始日期变化不自动改变目标期限、路线或成功标准。

## 4. 任务规格

每个任务至少包含：目标、执行说明、完成标准、预计时间、允许日期范围、是否可拆分、执行者、前置依赖和验证策略。

预计时间由 `expected_minutes`、`minimum_minutes`、`maximum_minutes` 和估算置信度表达。每日协调使用 expected 值，页面显示“约 N 分钟”；实际投入来自用户反馈，并用于改进后续估算。不能为了塞进当天预算而缩减完成标准。

执行者区分用户、Agent 和双方协作。Agent 生成辅助材料成功不能自动完成用户需要学习、训练或决策的任务。

## 5. 生成和预览

计划草稿由已确认目标档案、选中路线、领域策略、开始日期、共享时间预算、关联目标和可用能力共同生成。模型负责候选阶段、里程碑、任务内容和初始估算；服务端负责依赖无环、预算、日期、成功标准覆盖、能力可用性和跨目标约束。

预览页按以下顺序展示：

1. 目标结果和成功标准。
2. 选中路线及主要取舍。
3. 预计周期和每周投入。
4. 阶段时间线和退出条件。
5. 里程碑及验证方式。
6. 开始日起七天的详细任务、每日合计和预算余量。
7. 与其他目标的冲突、风险及规划假设。

计划草稿不进入今日页、不触发提醒，也不占用正式排期；预览必须使用当前时间预算检查可行性。

## 6. 修改边界

- 修改任务标题、说明或时间估算：更新草稿任务规格并重新校验。
- 移动允许范围内的日期、拆分任务或调整验证频率：局部重新排期。
- 修改阶段、里程碑、核心依赖或方法：创建新的计划草稿版本。
- 修改目标结果、成功标准、硬期限或关联目标：返回目标档案或路线阶段重新评估。

自然语言修改先转成结构化变更建议，服务端判定影响范围后再应用。模型不能直接写数据库或自行宣称变更属于小调整。

## 7. 开始执行

用户点击“开始执行”时，服务端重新检查目标档案、路线、开始日期、共享时间预算、任务依赖、关联目标、模型和必要能力，以及用户看到的草稿 revision。

全部通过后原子完成：激活计划版本、启用首批任务、更新目标状态、生成或刷新当天安排并写入审计/outbox。重复点击返回原成功结果；任何检查失败都不进行部分启用，并保留草稿供用户修正。

## 8. 验收场景

- 十二周计划只生成完整阶段和里程碑，以及首个七日窗口的详细任务，不一次创建十二周每日待办。
- 今天无剩余预算时默认下一个可用日期；用户改为更晚日期后首周预览同步移动。
- 首周详细任务总量超过共享预算时显示缺口，不通过缩短任务标准伪造可行。
- 路线不变的正常滚动展开创建新任务批次，不创建新的战略计划版本。
- 用户修改里程碑时创建新计划草稿，旧草稿和已完成记录保留。
- 双击“开始执行”只产生一个活动计划和一组正式任务。
