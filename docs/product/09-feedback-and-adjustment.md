# 任务反馈、验证与计划调整 v0.1

状态：首版产品方案已确认。目标是让反馈足够轻量，同时保证执行事实、结果验证和计划调整互不覆盖。

## 1. 用户反馈动作

任务详情提供以下主要动作：

- **开始**：把任务标记为进行中，不强制启动计时器。
- **完成**：记录用户已完成执行；普通任务可以一键提交，耗时可选。
- **部分完成**：记录已做内容、可选实际耗时和剩余情况，任务继续存在。
- **遇到阻碍**：记录阻碍类型和说明，可以请求 Agent 帮助；持久阻碍在解决前继续影响依赖和排期。
- **今天做不了**：只表示本日延期，任务仍为待执行；不等于任务失败或永久取消。
- **不再需要**：进入计划变更流程，不能作为普通完成或今日跳过处理。

用户可以更正误操作。更正追加新的执行记录并引用被更正记录，不删除原历史；如果后继任务已经因此启动，系统显示影响并重新评估。

## 2. 执行状态与验证状态

执行状态表达用户是否做了动作：`pending`、`in_progress`、`partial`、`completed`、`cancelled`。依赖或开放阻碍造成的 `blocked` 是计算状态，不覆盖执行历史。“今天做不了”保存在执行记录和每日安排中，任务通常仍是 pending/partial。

验证状态独立表达结果是否达到标准：`not_required`、`pending`、`passed`、`not_met`、`insufficient_evidence`、`error`。

因此允许同时出现：

```text
执行：已完成
验证：未达到标准
```

只要求“完成动作”的后继任务可以继续；要求“结果达标”的依赖必须等待 verification passed。验证失败不删除用户投入，也不把任务改回未执行。

## 3. 反馈交互成本

普通任务默认一键完成，实际耗时和备注可跳过；缺失耗时保存为 unknown，不能当作零。部分完成和遇到阻碍只收集完成本次调整所需的最少信息。练习、测评和交付任务在开始前就展示材料和验证要求，不能提交后临时增加标准。

每日回顾保持可跳过，建议只询问当天整体是否符合预期、时间估算是否明显偏差及是否有新限制。未填写回顾不阻止第二天使用。

## 4. 调整分级

调整是否自动执行，以是否仍在用户已批准的计划包络内判断。计划包络包括：目标和成功标准、路线方法、阶段/里程碑、已批准周投入、任务允许日期范围、用户锁定及关联目标边界。

| 等级 | 典型变化 | 处理方式 |
| --- | --- | --- |
| A0 记录 | 完成、耗时或困难，但无需改变未来安排 | 保存记录并解释当前状态 |
| A1 排期调整 | 重排、允许范围内移动、合法拆分 | 自动执行，展示原因和前后差异 |
| A2 计划内修正 | 同一里程碑内调整未开始任务、加入替代/补救任务，且不突破已批准投入和日期 | 由领域规则允许时自动执行，显式取消被替代任务并保留原因 |
| A3 重大计划变化 | 增加已批准投入、延期里程碑/期限、改变阶段或影响其他目标 | 生成待确认建议 |
| A4 目标变化 | 修改目标结果、成功标准、硬限制或关联关系 | 返回目标档案/路线重新确认 |

进行中和已完成任务不能被自动替换；用户锁定任务不能被自动移动。所有自动变化都写入日志，并允许用户查看原因。

## 5. 常见触发及处理

- **一次今天做不了**：在允许日期范围内重新安排，不把所有后续任务机械顺延。
- **同一任务连续两次部分完成、延期或遇阻**：停止继续堆积，询问简短原因或提供拆分/求助选项。
- **验证未达标**：根据领域规则安排复习、纠正或补充产出；只有在原周投入包络内才可自动加入。
- **实际耗时明显偏离估算**：先记录；积累至少三条可比较任务记录后再校准后续估算，避免一次异常改变整套计划。
- **没有反馈**：保持 unknown，不推断为未完成；用户回来时先询问实际情况和当前可用时间。
- **新限制或目标变化**：生成影响分析，不能作为普通排期调整吞掉。

“连续两次”和“三条可比较记录”是已确认的首版默认阈值，并由版本化策略管理，后续可根据实际试用调整。

## 6. 调整结果展示

反馈提交后立即显示已保存状态，不等待验证模型。若后续发生调整，展示：触发原因、哪些任务改变、时间和里程碑影响、是否自动生效以及如何撤销或提出其他要求。

重大建议至少提供“接受”“拒绝”“继续讨论”。接受时重新检查最新版本后原子应用；建议过期时显示新的差异，不能使用旧确认。拒绝后保留当前计划和冲突，不反复自动提出相同建议。

## 7. 验收场景

- 普通任务一键完成后立即保存，即使验证服务不可用也不丢失执行记录。
- 练习已做完但未达掌握标准时，同时显示 completed 和 not_met。
- “今天做不了”不取消任务，也不把用户标记为失败。
- 同一任务连续两次部分完成后，系统不继续添加相同任务副本，而是提出拆分或诊断。
- 补救任务能放入原周投入时可以自动加入；需要额外增加投入时必须确认。
- 用户更正误完成记录后，历史保留，受影响的后继任务重新评估。
